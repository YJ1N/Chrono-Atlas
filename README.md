# ChronoAtlas

**역사 웹사이트가 아니라 Time Engine 입니다.**

Google Maps 에서 장소를 탐색하듯 시간을 탐색합니다. 138억 년부터 하루까지 연속으로 줌하며, 줌 레벨에 따라 보이는 사건의 밀도가 달라집니다 — 세계 줌에서 국가만, 거리 줌에서 카페까지 보여주는 지도와 같은 원리입니다.

역사는 첫 데이터셋일 뿐입니다. 엔진은 아키텍처 변경 없이 다른 도메인(기술, AI, 기업, 과학, 스포츠, 음악, 문화)을 받도록 설계했습니다.

---

## 이 프로젝트에서 실제로 어려운 것

렌더링이 아닙니다. 세 곳입니다.

**1. 숫자 표현** — JavaScript `Date` 는 ±271,821년까지만 표현합니다. 목표는 138억 년입니다. `Date` 를 코어 타입으로 잡으면 첫날부터 전제가 깨집니다.
→ `TimePoint = number` (천문학적 연도 float64). 실측 해상도는 서기 2026년에서 14μs, 138억 년 전에서 96초 — 정밀도가 필요한 구간에서 남고 무의미한 구간에서만 성깁니다. [ADR-001](DECISIONS.md)

**2. 뷰포트 수치 안정성** — 138억 년 → 하루는 약 5e12배 줌입니다. `d3-zoom` 처럼 배율 스칼라를 누적하면 float 정밀도가 무너져 패닝이 떨립니다.
→ 뷰포트를 `{center, span}` 으로 직접 소유합니다. 거대한 누적 스칼라가 없어 전 구간 안정적입니다. [ADR-002](DECISIONS.md)

**3. Y축이 무엇이고, 줌이 무엇을 바꾸는가** — 시간은 1D 입니다. Maps 가 Maps 인 이유는 2D 공간 + *줌별 의미 수준 변화* 때문입니다. 그냥 1D 로 만들면 지도가 아니라 슬라이더입니다.
→ Y축은 **연속적인 중요도**이며 줌에 결합되어 있습니다 — 확대하면 중요도 하한이 내려가 사소한 사건이 떠오릅니다. 그리고 줌은 배율이 아니라 **표현 자체**를 바꿉니다. [ADR-012](DECISIONS.md) · [ADR-013](DECISIONS.md)

> 첫 시도에서는 이것을 범주형 레인(가로 트랙)으로 만들었습니다. 그건 Y축이 아니라 스프레드시트의 행 머리글이었고, 결과물은 Gantt 차트였습니다. 무엇이 왜 실패했는지는 [ROADMAP.md](ROADMAP.md) 의 Phase 2R 절에 아홉 항목으로 기록해 두었습니다.

## 현재 상태

**Phase 4 완료** — 실데이터 **7,182건** · 단위 테스트 **328개** + 브라우저 검증 **54개 항목** 통과

화면은 차트가 아니라 **풍경**입니다. X는 시간, Y는 중요도(연속)이고, 배경의 밀도 지형이 "그때 무슨 일이 얼마나 있었는가"를 보여줍니다. 능선을 뚫고 솟은 봉우리가 랜드마크입니다.

**줌은 배율이 아니라 표현을 바꿉니다.** cosmic → epochal → historical → detail → moment 다섯 단계에서 그려지는 것 자체가 달라집니다 — 넓은 쪽에서는 지형과 시대 밴드가 주인공이고 개별 사건이 존재하지 않으며, 좁은 쪽에서는 지형이 사라지고 사건이 카드가 됩니다.

| 요소 | 역할 |
|---|---|
| 밀도 지형 (Canvas) | 화면을 채운다 — 빈 픽셀이 없다 |
| 봉우리 (SVG) | X=시간, Y=중요도. 확대하면 사소한 것이 떠오른다 |
| 로그 수평선 | 138억 년 전체 + 현재 위치. 주변시 |
| 시대 밴드 | 넓은 티어에서만 나타난다 |
| 콜드 오픈 | 4.2초 만에 규모를 설명 없이 전달 |
| ⌘K 검색 | 전 항목 7,182건. 아직 받지 않은 청크의 사건도 찾는다 |
| URL 딥링크 | 본 화면을 그대로 공유. 도달 가능한 모든 뷰포트에서 오차 0px |

**브라우저 실측** (1440×900, 연속 팬·줌 부하, 실데이터 7,182건):
p50 프레임 간격 **16.7ms = 60fps**, 드롭 **0%**.

데이터는 Wikidata 에서 뽑아 커밋합니다 — **런타임 API 는 0개**입니다. 첫 페인트에는
상위 중요도 884건만 번들로 들어가고(416KB), 나머지는 뷰포트에 따라 지연 로드됩니다.
검색 색인은 ⌘K 를 처음 열 때만 받습니다.

> 성능과 시각적 주장을 **측정합니다.** `npm run verify:browser` 가 Playwright 로
> 프레임을 재고, 캔버스 픽셀을 세어 "지형이 화면을 채우는가"를 확인합니다.
> 이 검증이 단위 테스트로는 잡히지 않는 버그를 여러 번 잡았습니다 —
> 포인터 캡처로 인한 클릭 실패, StrictMode 이중 실행으로 멈춘 인트로,
> 공유한 링크가 실제로 본 화면과 미묘하게 달랐던 문제,
> 모달에서 결과 목록으로 Tab 하면 Escape 가 먹지 않던 문제 등.
>
> 특히 접근성은 `element.focus()` 를 프로그램으로 부르면 전부 통과하지만
> 실제로 `Tab` 을 누르면 드러납니다. 그 차이로 네 가지 결함을 찾았습니다.

다음은 Phase 5 (마감·배포). [ROADMAP.md](ROADMAP.md)

## 아키텍처 불변식

의존은 한 방향으로만 흐릅니다.

```
components/ ─▶ engine/
domains/    ─▶ engine/
engine/     ─▶ (아무것도 참조하지 않는다)
```

`engine/` 이 `domains/` 를 참조하는 순간 "Time Engine" 이라는 주장은 무너집니다. 그래서 이 규칙은 문서가 아니라 **ESLint 로 강제**되며, 위반 시 `npm run lint` 가 실패합니다. `engine/` 안의 `Date` 사용도 같은 방식으로 차단됩니다.

**진짜 시험:** `domains/history` 를 지우고 `domains/ai` 를 넣었을 때 `engine/` 이 0줄 변경인가. Phase 6 의 목표입니다.

## 실행

```bash
npm install
npm run dev             # 개발 서버 → http://localhost:3000
npm run verify          # lint + typecheck + test
npm run test:watch      # 시간 커널 개발 중
npm run build           # 프로덕션 빌드 (정적 프리렌더)

# 브라우저 실측 (다른 터미널에 dev 서버가 떠 있어야 합니다)
npm run verify:browser

# 데이터 재생성 — 평소엔 불필요합니다. 산출물이 커밋되어 있습니다.
npm run etl:probe       # 쿼리가 WDQS 60초 제한을 통과하는지만 점검
npm run etl             # Wikidata 수집 → 산출물 + 검증 리포트
```

**써 볼 것** — 콜드 오픈이 끝나면

| 조작 | 결과 |
|---|---|
| 드래그해서 던지기 | 관성으로 계속 흐르다 멈춥니다 |
| 휠 / 트랙패드 핀치 | 줌. 다섯 티어에서 그려지는 것 자체가 바뀝니다 |
| `⌘K` 또는 `/` | 사건 검색 (예: `아폴로`, `전투`, `빅뱅`) |
| 헤더의 **138억 년** | 우주 전체 — 지형만 남고 개별 사건이 사라집니다 |
| 봉우리 클릭 | 상세 패널 + 그 시대 언저리로 이어지는 관계 칩 |
| `Tab` | 이름이 보이는 사건 사이를 키보드로 순회 |
| 주소창 | 보고 있는 화면이 그대로 URL 에 담깁니다. 복사해서 새 탭에 붙여넣어 보세요 |

Node 26 / npm 11 · Next.js 16 (App Router, Turbopack) · React 19 · TypeScript 5 strict · Tailwind CSS 4 · motion 12 · Vitest 4 · Playwright

**의도적으로 넣지 않은 것**

- **D3** — 시간축 스케일·눈금을 직접 소유하는 편이 짧고 정확했습니다. 특히 `d3-array` 의 `ticks()` 는 1-2-5 사다리만 알아서 시간축에 쓸 수 없습니다 — 그 아래에 달력이 있어 `1/12`·`1/365` 같은 비-10진 단위로 내려가야 하고, 라벨도 `"1969.4521"` 이 아니라 `"Jul 1969"` 여야 합니다. [ADR-008](DECISIONS.md)
- **TanStack Query** — 런타임 API 가 0개면 서버 상태 라이브러리는 해결할 문제가 없습니다. [ADR-007](DECISIONS.md)
- **기성 타임라인 라이브러리** — 138억 년 동적 범위도 중요도 기반 LOD 도 지원하지 않습니다.
- **Zustand** — 계획에 있었고 설치까지 했으나 Phase 4 까지 와도 전역으로 나눌 상태가 없어 제거했습니다. 뷰포트는 `ViewportController`, 선택은 컴포넌트, 청크는 모듈 캐시가 들고 있습니다.
